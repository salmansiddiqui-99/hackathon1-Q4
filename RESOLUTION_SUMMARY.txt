TECHNICAL DETAILS:
==================

Root Cause Analysis:
--------------------
The OpenRouter adapter was implemented expecting only LLMMessage dataclass
instances with .role and .content attributes. However, some calling code was
passing plain dictionaries with ["role"] and ["content"] keys instead.

When the adapter tried to access msg.role on a dictionary, Python raised:
  AttributeError: 'dict' object has no attribute 'role'

This caused all completion requests to fail immediately, breaking the entire
AI Assistant functionality.

Fix Strategy:
-------------
Instead of enforcing a single format, the fix makes the adapter flexible to
handle BOTH formats:
1. LLMMessage objects (with attributes)
2. Plain dictionaries (with keys)

Implementation uses isinstance() check to detect the type and access the data
appropriately. This maintains backward compatibility while fixing the error.

Error Prevention:
-----------------
Future improvements:
1. Add type hints: Union[LLMMessage, dict]
2. Add runtime validation with Pydantic
3. Add unit tests for both message formats
4. Add integration tests for chatbot service
5. Add logging for format detection
