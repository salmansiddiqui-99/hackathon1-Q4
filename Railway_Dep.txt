SECTION 1: QUICK DEPLOYMENT STEPS
================================================================================

STEP 1: Create Railway Project
-------------------------------
1. Go to https://railway.app and log in
2. Click "New Project"
3. Select "Deploy from GitHub repo"
4. Choose repository: salmansiddiqui-99/hackathon1-Q4
5. Select branch: 001-phase1-setup
6. Railway will auto-detect the backend service

STEP 2: Configure Service Settings
-----------------------------------
1. After project creation, click on the backend service
2. Go to "Settings" tab
3. Configure the following:

   Root Directory: backend
   Build Command: (leave default or use: pip install -r requirements.txt)
   Start Command: uvicorn src.main:app --host 0.0.0.0 --port $PORT

   OR if using Nixpacks (recommended):
   - Railway will auto-detect Python
   - It will use pyproject.toml or requirements.txt
   - Start command: uvicorn src.main:app --host 0.0.0.0 --port $PORT

STEP 3: Add Environment Variables
----------------------------------
Go to "Variables" tab and add all variables from SECTION 2 below.

STEP 4: Deploy
--------------
1. Click "Deploy" button (or it will auto-deploy)
2. Wait for build to complete (2-5 minutes)
3. Once deployed, Railway will provide a public URL
4. Copy the URL for frontend configuration

STEP 5: Verify Deployment
--------------------------
1. Open the Railway URL in browser
2. Add /health to the URL: https://your-app.railway.app/health
3. Should return JSON with "status": "healthy"
4. Check logs for startup messages

SECTION 3: RAILWAY-SPECIFIC CONFIGURATION
================================================================================

PORT Configuration:
-------------------
Railway automatically provides $PORT environment variable.
Your start command MUST use it:

  uvicorn src.main:app --host 0.0.0.0 --port $PORT

DO NOT hardcode port 8000 in production.


Public URL:
-----------
After deployment, Railway generates a URL:
  https://your-backend-production-xxxx.up.railway.app

This URL should be used in your frontend configuration:
  - Update frontend .env with: VITE_API_URL=https://your-backend-url
  - Add Railway URL to CORS_ORIGINS


Health Check:
-------------
Railway can use health checks to verify service is running.
Endpoint: /health
Expected response: {"status": "healthy"}

Configure in Settings → Health Check:
  Path: /health
  Expected Status: 200


Logging:
--------
View logs in Railway Dashboard → Logs tab
All Python print() and logging.logger() calls appear here
Use LOG_FORMAT=json for structured logging


Auto-Deploy:
------------
Railway can auto-deploy on git push:
  Settings → GitHub → Enable "Auto-deploy on push"
  Select branch: 001-phase1-setup

SECTION 5: COMMON DEPLOYMENT ISSUES & SOLUTIONS
================================================================================

ISSUE 1: "GEMINI_API_KEY is required" Error
--------------------------------------------
CAUSE: Railway is running old/stale code
SOLUTION:
  1. Go to Railway Dashboard → Deployments
  2. Check commit hash - should be 5a033b6 or later
  3. If older commit, click "Redeploy" to pull latest code
  4. Verify environment: LLM_PROVIDER=openrouter
  5. Remove any GEMINI_API_KEY variable if present


ISSUE 2: Build Fails with "No module named 'src'"
--------------------------------------------------
CAUSE: Incorrect working directory
SOLUTION:
  1. Settings → Root Directory: backend
  2. Redeploy


ISSUE 3: Port Binding Error
----------------------------
CAUSE: Not using Railway's $PORT variable
SOLUTION:
  Start command must be:
    uvicorn src.main:app --host 0.0.0.0 --port $PORT


ISSUE 4: CORS Errors from Frontend
-----------------------------------
CAUSE: Railway URL not in CORS_ORIGINS
SOLUTION:
  1. Copy Railway public URL
  2. Add to CORS_ORIGINS variable:
     CORS_ORIGINS=https://railway-url.railway.app,https://username.github.io


ISSUE 5: Database Connection Failed
------------------------------------
CAUSE: Invalid DATABASE_URL or network issue
SOLUTION:
  1. Verify DATABASE_URL format includes ?sslmode=require
  2. Test database is accessible
  3. Check if using Railway Postgres - use $DATABASE_URL variable


ISSUE 6: "Module not found" Errors
-----------------------------------
CAUSE: Dependencies not installed
SOLUTION:
  1. Verify requirements.txt exists in backend/
  2. Check build logs for pip install errors
  3. Ensure all dependencies listed in requirements.txt


ISSUE 7: Slow Response Times
-----------------------------
CAUSE: Cold starts or insufficient resources
SOLUTION:
  1. Upgrade Railway plan for better performance
  2. Consider keeping service warm with uptime monitors
  3. Check OPENROUTER_MODEL - some models are slower


ISSUE 8: Out of Memory (OOM)
-----------------------------
CAUSE: Insufficient RAM allocation
SOLUTION:
  1. Reduce DB_POOL_SIZE to 3
  2. Reduce BATCH_SIZE to 50
  3. Upgrade Railway plan for more memory

  - Service downtime

Backups:
--------
Database:
  - Enable automated backups in your DB provider
  - Test restore procedure regularly

Environment Variables:
  - Keep backup copy in password manager
  - Document all changes


Updates:
--------
To deploy new code:
  1. Push changes to GitHub branch 001-phase1-setup
  2. Railway auto-deploys (if enabled)
  3. OR manually trigger deploy in Dashboard
  4. Monitor logs for successful startup


Rollback:
---------
If deployment fails:
  1. Deployments tab → Previous successful deployment
  2. Click three dots (⋮) → "Redeploy"
  3. Railway restores previous version

SECTION 8: CONNECTING FRONTEND TO RAILWAY BACKEND
================================================================================

After Railway deployment is complete:

STEP 1: Get Railway Backend URL
--------------------------------
From Railway Dashboard, copy your backend URL:
  Example: https://physical-ai-backend-production.up.railway.app


STEP 2: Update Frontend Environment
------------------------------------
In your frontend project, create/update .env file:

  VITE_API_URL=https://your-railway-backend-url.railway.app

Or if using Next.js:
  NEXT_PUBLIC_API_URL=https://your-railway-backend-url.railway.app


STEP 3: Update CORS on Backend
-------------------------------
Add frontend URL to Railway environment variables:

  CORS_ORIGINS=https://salmansiddiqui-99.github.io/hackathon1-Q4,https://your-railway-backend-url.railway.app,http://localhost:3000


STEP 4: Rebuild Frontend
-------------------------
After updating .env:
  npm run build
  npm run deploy (for GitHub Pages)


STEP 5: Test Connection
------------------------
1. Open frontend in browser
2. Open browser DevTools → Network tab
3. Try AI Assistant query
4. Verify API calls go to Railway URL
5. Check for 200 OK responses
